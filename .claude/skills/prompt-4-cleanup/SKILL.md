# Prompt 4: extract static code generation from the {lang} emitter

Substitute `{lang}` with the emitter identifier the user named. If they did not
name one, ask which language first.

**Step 0.** Read `docs/lang-gen/workspace.md` in this repo for path resolution,
the generate command, and the persistence policy. Also read
`docs/sdk-architecture/{lang}.md` — where it exists, it is the authority on which
files this language expects to be hand-maintained.

It does not exist for every emitter, and extraction is the one prompt where that
gap actually bites: you are deciding which files change owner, so guessing is
expensive. If the doc is missing, reconstruct the split from code using the
fallbacks in `workspace.md` (grep `@oagen-ignore-file` in the target,
`skipIfExists` in the emitter, read `src/{lang}/index.ts`), state the split you
inferred **before** moving anything, and consider writing the design doc as part
of this work — it is the artifact that keeps the next run from re-deriving it.

## Where this sits

Fourth in the sequence: prompt-1 (generate + validate), prompt-2 (spec endpoint
coverage), prompt-3 (non-spec coverage), **prompt-4 (this one)**, prompt-5
(blanket sanity). It assumes the emitter already produces a working SDK — if it
does not, run prompt-1 first.

## Goal

Some emitter code generates **static** output: identical regardless of the
OpenAPI spec. That code should live directly in the target SDK as
hand-maintained files marked `@oagen-ignore-file`, not be regenerated on every
run. Only spec-dependent output — models, enums, resources, service wiring,
per-service tests — stays in the emitter.

## Step 1: Audit each generator for static vs dynamic output

For each generator in `src/{lang}/` (`client.ts`, `config.ts`, `errors.ts`,
`tests.ts`, …), classify its output:

- **Fully static** — identical regardless of spec. Candidates: HTTP client
  infrastructure, error class hierarchies, type utilities, pagination classes,
  project config files (`pyproject.toml`, `composer.json`, `package.json`,
  `build.gradle.kts`), test helpers, conftest, and client-behavior fixtures
  (retry, error raising, idempotency).
- **Mostly static with small dynamic parts** — typically the client file: mostly
  HTTP infrastructure, but the service accessor properties are spec-driven.
- **Fully dynamic** — depends on spec models/enums/services/operations. Stays in
  the emitter.

## Step 2: Split the client file

The client file usually holds the most static code. Apply this pattern:

1. **Create a base client file** in the target SDK (`_base_client.py`,
   `BaseClient.php`, `base-client.ts`, …) marked `@oagen-ignore-file`. It holds
   all HTTP infrastructure: base class, request/retry/error-raising logic, header
   building, pagination helpers, context managers / destructors.
2. **Slim the generated client file** down to importing from the base and
   defining thin subclasses that contain only spec-driven service accessors.
3. **Compat accessors** (hand-written modules like passwordless, vault, actions,
   pkce) MUST go in the **generated** client file, not the base. Their
   constructors type-hint against the full subclass, and `self` / `$this` in the
   base class does not satisfy that constraint. Proven during the Python
   extraction, which produced
   `"WorkOSClient*" is not assignable to "WorkOSClient"` until they were moved.

## Step 3: Move fully static files to the target SDK

For each fully static file:

1. In the target SDK, replace the auto-generated header (e.g.
   `# This file is auto-generated by oagen. Do not edit.`) with
   `# @oagen-ignore-file` — using the language's comment syntax
   (`// @oagen-ignore-file` for node/php/kotlin/go, `-- ` or `#` as appropriate).
2. In the emitter, delete the generator's file entirely and replace the method
   body in `index.ts` with `return []`.
3. Remove the now-dead import from `index.ts`.

Inline `return []` directly — do not leave unused parameters like `_ctx` in
no-op methods; the linter flags them.

## Step 4: Remove static test generation

Static test files (conftest/helpers, client-behavior tests, pagination tests)
move to the target SDK with `@oagen-ignore-file`. Remove their generator
functions from the emitter's `tests.ts`. Keep dynamic test generation:
per-service tests, model round-trip tests, fixture JSON.

**After the client split**, hand-maintained tests that monkeypatch module-level
attributes must point at the base client module. Python's tests had
`monkeypatch.setattr(generated_client_module.time, "sleep", ...)` and had to
switch from `_client` to `_base_client`, since `time` and `asyncio` moved there.

## Step 5: Update emitter tests

- Rewrite tests for slimmed generators. The client test should now assert
  subclass definitions and service accessors — not HTTP infrastructure, retry
  logic, or error handling.
- Delete or reduce tests for deleted generators; assert the interface method
  returns `[]`.
- Leave no unused imports — lint/typecheck pre-push hooks will catch them.

## Step 6: Verify end to end

```bash
# 1. Emitter checks
cd "$EMITTERS"
npm test
npm run typecheck
npm run lint
```

2. Generate per the Generation section of `docs/lang-gen/workspace.md`.

3. Confirm every `@oagen-ignore-file` file still carries that header rather than
   the auto-generated one — that is the proof generation did not overwrite it.

4. Confirm no staging-only files leaked into the target repo. Files marked
   `integrateTarget: false` (e.g. `smoke-manifest.json`) belong only in the
   staging directory:

   ```bash
   test ! -f "$SDK_TARGET/smoke-manifest.json"
   ```

5. Target SDK checks:

   ```bash
   cd "$SDK_TARGET"
   script/ci
   ```

All of these must pass cleanly before committing.

## Errors to watch for

These came up during the Python extraction and tend to recur.

**Type-checker errors from the client split**

```
"WorkOSClient*" is not assignable to "WorkOSClient" (reportArgumentType)
```

A compat accessor is on the base class while its constructor type-hints the
generated subclass. Fix: move the accessor to the generated client file.

**Unused imports after extraction**

```
F401 `functools` imported but unused --> _base_client.py
```

Moving `cached_property` accessors out of the base client orphans imports like
`functools`. Check both the target SDK files and the emitter source.

**Monkeypatch targets in hand-maintained tests**

```
"time" is not a known attribute of module "._client" (reportAttributeAccessIssue)
```

Tests monkeypatching `_client.time.sleep` or `_client.asyncio.sleep` must switch
to `_base_client` after the split. Mark those test files `@oagen-ignore-file` so
they are not overwritten.

**TypeScript errors in emitter tests**

```
TS2554: Expected 1 arguments, but got 0.
```

A deleted generator's test calls the method without the required `ctx`. Pass a
dummy context or test through the emitter object — do not leave an unused `_ctx`.
